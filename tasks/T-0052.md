# T-0052 — Main menu and the boot flow

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2D — entry point
Status: open

## Goal

The game opens on a **main menu** with *Start Game* and *Exit*. Start Game begins a run at
the map screen; Exit closes the game. The menu is built so more options can be added later
without restructuring it.

## Context

- `src/ui/run_map_screen.gd` — the map screen, already built and passing 71 checks
- `src/gameplay/run_flow.gd` — `start_run(seed)`, `enter_node()`, signals `map_ready`,
  `level_opened`, `level_completed`
- `src/ui/map_input.gd` — the input abstraction, bound to `game_focus_next/prev/confirm/dismiss`
- `docs/CHARTER.md` — gamepad-first; menus are otherwise a G3 item, but the entry point is
  needed now for G2.2

## Scope

1. **`main_menu` scene** — a vertical list of options, driven by data (an array of
   `{id, label, action}` entries) rather than hardcoded branches, with focus, confirm and
   dismiss handled through the existing input abstraction. Entries today: **Start Game**,
   **Exit**. Adding a third must be one entry, no new code.
2. **A boot scene** that owns the run and the screens: menu → (Start) → map screen → (node
   entered) → level → (level completes) → map screen → … → menu again when the run ends.
   Exit quits the application.
3. **Headless autostart**, so gates can exercise real gameplay from the same entry point:
   if `--autostart` is passed, skip the menu and begin a run immediately. This exists so
   `smoke.ps1` keeps testing the game rather than an idle menu.
4. The arena stays the level scene; the boot scene instantiates it per level.
