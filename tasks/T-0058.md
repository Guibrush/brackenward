# T-0058 — A starting loadout, so a run is playable

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2E — playability
Status: open

## Goal

A run begins with something to place. Today the inventory starts empty, so the build panel —
which works — has nothing to list.

## Context

- `src/gameplay/run_flow.gd` — `start_run(seed)`; owns the inventory
- `src/systems/inventory.gd` — `add_tower(type_id, tier, slots)`, `add_upgrade(type_id)`
- `src/gameplay/item_catalogue.gd` — the (item, tier) pairs from the design tables
- `docs/design/systems/towers.md` — the six towers and their tiers

## Decision already made by the human

A run opens with **a choice between two tier-1 towers and two tier-1 upgrades**. The choice
screen is **not** in this task — that is UI for later. This task grants a **default loadout**
so the loop can be played now, from a data table, so the choice screen can replace the grant
without touching anything else.

## Scope

1. A **data-driven starting loadout** on the session: a list of `{kind: tower|upgrade, type_id,
   tier}`, exported, with a small default of two distinct tier-1 towers and two tier-1
   upgrades drawn from the catalogue.
2. `start_run()` grants it into the inventory **before** the map is ready, so the first build
   phase has something to place.
3. A missing or empty loadout is **refused loudly** — a run with nothing to place is a broken
   run, not a quiet one.
4. Note in the file header that this is a placeholder for the choice screen.

## Definition of done — with planted failures

1. `--check-only`, pasted.
2. A run started from seed shows a **non-empty inventory** in the printed snapshot: two towers
   at tier 1 with distinct types, two upgrades, and the build panel's list non-empty when the
   level opens.
3. **Planted failure A:** empty the loadout table and show the run refusing to start with a
   printed reason rather than opening an unplayable level.
4. **Planted failure B:** point a loadout entry at a type the catalogue does not have, and show
   the refusal naming it.
5. `tests.ps1` 5/5 and the short `smoke.ps1` probe unchanged (`stuck 0`, no error lines).
