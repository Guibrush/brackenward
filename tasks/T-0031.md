# T-0031 — Sentinel and restore for any in-place mutation

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2A — process hardening
Status: open

## Goal

If anything ever mutates the real tree again, the fact is impossible to miss and
recoverable in one command. T-0030 removes the need; this makes the exception loud and
reversible rather than silent and lossy.

## Work

1. **Sentinel.** Any in-place mutation writes `.mutation-active` at the repository root
   before touching a file, containing the ISO timestamp, the agent id, the task id and
   the list of paths. It is removed only after the restore is verified.
2. **Backup manifest.** The same write records each mutated path, its backup path under
   `.mutation-backup/`, and the original SHA-256.
3. **`scripts/gate/restore.ps1`.** Restores every path from the manifest, re-verifies the
   SHA-256 against the recorded value, deletes `.mutation-backup/` and the sentinel, and
   exits 0 only when every hash matches. No sentinel → exit 3 (`blocked`, nothing to do),
   not a pass. Hash mismatch after restore → exit 1, naming the file.
4. **Gate check.** A check that fails loudly when `.mutation-active` exists, so a mutated
   tree cannot pass a gate run. Preserve the sentinel contents in the failure detail.
5. **`.gitignore`.** Add `.mutation-active` and `.mutation-backup/` so a mutation can
   never be committed. The gate check is what makes it loud; git is what makes it
   uncommittable.

## Constraints

- You may write `scripts/gate/restore.ps1`, a new gate check script under `scripts/gate/`,
  `scripts/gate/all.ps1` (to include the check), and `.gitignore`.
- Do not modify `src/**`, `assets/**`, `scenes/**`, `project.godot`, or
  `scripts/gate/prove-failure.ps1`.
- No git commands; `studio-lead` commits with `Agent: eng/tools`, `Task: T-0031`.
- Zero generations.

## Definition of done — every line observed

1. **Stale sentinel fails the suite.** Create `.mutation-active` with plausible contents,
   run `powershell -NoProfile -File scripts/gate/all.ps1 -Gate G2`, and show the suite
   failing with the sentinel contents quoted. Paste it.
2. **restore.ps1 clears it.** With one real mutated file plus a matching backup and
   manifest, run `restore.ps1`: it restores the file, the SHA-256 matches the recorded
   value, the sentinel and backup directory are gone, `git status` is empty. Paste the
   hashes.
3. **Nothing to restore** → exit 3, `blocked`, not pass.
4. **Hash mismatch** → exit 1 naming the file, and the sentinel is **not** removed.
5. The new gate check appears in the suite summary and reports `pass` on a clean tree.
6. `all.ps1 -Gate G2` is otherwise unchanged: same criteria, same exit-code meanings.

## Do not

- Do not make the sentinel check depend on git status; a mutated file can be committed
  by an agent that ignores status, which is exactly the case this must catch.
- Do not let `restore.ps1` delete a sentinel it could not satisfy.

## Return

The standard envelope with all six items and `FILES TOUCHED`.
