## Goal

One generated tower sprite passes `scripts/gate/assets.ps1` with a real manifest entry.
The asset gate has only ever been exercised against fixtures, and PR #8 changed how it
reads the manifest — so the first real sprite is the test, not the first batch.

**Budget: 1 PixelLab generation.** If the gate rejects the result, stop and report;
do not retry and do not tweak the gate.

## The asset

The basic arrow tower, the same subject as the anchor so the two can be compared:
`assets/art/towers/arrow/idle/south.png`, 64×64, single direction, one frame.

Requirements: pixel art from `create_map_object`, palette snapped to the 16 locked
hexes with the free workbench, 1px `#1b1a26` outline on the silhouette, binary alpha,
**ground pad cropped**, ≤12 tones, no colour outside the palette.

## Definition of done

1. The PNG exists at the path above, 64×64, and is registered in `art/manifest.json`
   with `placeholder: true`, a real `prompt`, `generator`, `cost`, `license`, and
   `frames` listing the file.
2. `powershell -NoProfile -File scripts/gate/assets.ps1` exits 0 with G2.4 and G2.5
   passing. Paste the output.
3. Palette check: paste the distinct opaque colour count and confirm zero off-palette.
4. State whether the ground pad was cropped and how (crop, mask, or redraw), and paste
   the before/after byte or pixel evidence.
5. If the gate rejects the real asset — schema mismatch, palette, missing frame, size
   — **stop**, report the exact rejection, and flag that all batch art is blocked.
6. Return `FILES TOUCHED` as exact paths for `studio-lead` to commit.
