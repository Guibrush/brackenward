## Goal

Branch protection applies to `main` and `dev`, so `repo.ps1` reports G1.2 and G1.3
as passing. Two defects in `scripts/git/protect.ps1` currently make that impossible,
and both must be fixed: the payload it sends is malformed, and the script reports
success when it has failed.

## The two defects, already diagnosed

**1. BOM in the JSON body (P1).** `protect.ps1:54` writes the request body with
`Set-Content -Encoding utf8`. Under Windows PowerShell 5.1 that emits a UTF-8 BOM
(`EF BB BF`), and `gh api --input` sends the file verbatim. GitHub answers
`400 Problems parsing JSON`, so neither branch is ever protected. The mechanism was
reproduced with a byte-identical body against a side-effect-free endpoint: with BOM
→ 400, without BOM → 200. Note the discriminator trap: probing against a nonexistent
branch returns `404 Branch not found` regardless of body validity, because branch
lookup precedes body parsing — a 404 there proves nothing.

**2. Unconditional `exit 0` (P1).** `protect.ps1:95` ends with `exit 0`, so the
script reports success after failing. `init-repo.ps1:141`'s
`if ($protect.ExitCode -ne 0)` guard is dead code as a result.

## Definition of done

1. The payload is written without a BOM. Prove it by reading the first three bytes of
   the file the script produces — `EF BB BF` must be absent.
2. A failed protection call makes the script exit non-zero. Prove it by observing a
   deliberate failure (a malformed payload or an unreachable endpoint) produce a
   non-zero exit, then restore the script.
3. `powershell -NoProfile -File scripts/git/protect.ps1` exits 0 and reports both
   branches protected.
4. `powershell -NoProfile -File scripts/gate/repo.ps1` exits 0 with G1.1, G1.1.b,
   G1.2, G1.3, and G1.4 all passing. Paste every line.
5. `gh api repos/Guibrush/brackenward/branches/main/protection` and the same for
   `dev` both return JSON, pasted, showing the required settings rather than a 404.
6. Commit the script fix on a branch and push it. Do not merge it yourself.

- Do not weaken protection, disable a check, or exempt a branch to get green.
- Do not touch the CI workflow; CI is already green and does not run `repo.ps1`.
