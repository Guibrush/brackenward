# T-0065 — The blocking choice modal, starting with the opening pick

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2G — UI structure
Status: open

## Goal

A reusable **blocking choice modal** that sits over the map, and the first use of it: the
opening choice of **one tower and one upgrade** before the first node is selected.

Built for reuse — the event node and the store will use the same component later. Design the
API for that now; only the opening pick is wired in this task.

## What the human decided

- One **tower** from two, and one **upgrade** from two.
- The modal is **over the map**, which stays visible but **inert** until the choice is made.
- **Unchosen items remain acquirable later** — the choice is a head start, not an exclusion.
- It must return for events and the store, so the component takes a title, groups, and a
  selection rule rather than hardcoding "tower and upgrade".

## Context

- `src/gameplay/run_flow.gd` — `start_run()` currently **grants** the whole placeholder loadout
  (two towers, two upgrades). That changes here: the run starts with **nothing granted**, and
  the modal grants the two picks.
- `src/ui/boot.gd` — starts the run and shows the map screen; the modal belongs between
  `start_run()` and the first node being selectable.
- `src/ui/run_map_screen.gd`, `src/ui/map_input.gd` — input abstraction and the existing row
  pattern.
- `src/systems/inventory.gd` — `add_tower`, `add_upgrade`.

## Scope

1. **`ChoiceModal`** — title, one or more groups, each group offering N items and requiring
   exactly one pick; confirm is refused until every group has a pick; no dismiss without
   choosing. Emits the picks.
2. **Blocking**: while visible, the map screen receives nothing — clicks and keys are consumed
   by the modal. Prove it.
3. **Opening pick**: after *Start Game*, the modal appears over the map with the two towers and
   two upgrades; confirming grants exactly the picked tower and upgrade to the inventory.
4. **Run state**: nothing is granted before the choice; the run does not stall if the modal is
   somehow skipped — that case must refuse loudly rather than start an empty run.

## Definition of done — evidence through the real path

1. `--check-only`, pasted.
2. A demo driving the **real boot path** with **real pushed events**: Start Game → modal over

   confirm → inventory holds exactly those two items, and the map becomes interactive.
3. **Planted failure A:** confirm with only one group chosen — refused with a printed reason,

4. **Planted failure B:** attempt to dismiss the modal — refused; the run cannot proceed around
