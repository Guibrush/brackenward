# T-0025 — Main scene with one playable entity

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2A — critical path
Status: open

## Goal

A main scene exists, runs headless without errors, and contains one enemy that walks
a path and dies at the end of it. This is the thing `smoke.ps1` and `tests.ps1` will
later exercise; without it those gates can only report `blocked`.

## Context

- `docs/gates/G2-vertical-slice.md` — G2.1 is now a 300 s stability run (ADR-0002)
- `art/STYLE.md` — 32×32 tiles, isometric 3/4 sprites on a square grid
- `docs/CHARTER.md` — run structure: HQ at the end of the path, leaks damage it
- `docs/LESSONS.md` — L-021 (an unobserved failure is not evidence)

## Scope, deliberately small

One straight lane across a small board. One tower node that does nothing yet. One
enemy that spawns, follows the lane, and despawns at the end, decrementing HQ health
once. No art dependency: use `ColorRect` or `Polygon2D` shapes so this cannot block
on the art probe.

## Constraints

- You may write `scenes/**` and `src/gameplay/**` only.
- **Do not edit `project.godot`** — setting `run/main_scene` is `eng/tools`' file, and
  T-0026 does it. Verify your scene by passing it explicitly on the command line.
- No git commands; `studio-lead` commits with `Agent: eng/gameplay`, `Task: T-0025`.
- Budget: 0 generations.

## Definition of done — with a planted failure

1. The scene loads and runs headless for at least 10 s with **zero** error lines.
   Paste the command and its output.
2. The enemy walks the lane and the HQ health drops by exactly one when it arrives.
   Print both numbers.
3. **Planted failure:** break the enemy's despawn handler on purpose, run the same
   command, and show it producing an error or a stuck entity. Restore it and show the
   clean run again. This proves the check you will rely on can fail.
4. `FILES TOUCHED` as exact paths.

## Return

The standard envelope with both runs' output, the HQ before/after numbers, and the
planted failure described precisely.
