# T-0078 — Drag a tower out of the bar

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2H — inventory interaction
Status: open

## Goal

A player can press on a tower slot and **drag it onto the board**. This task builds the
bar's half only: the gesture, the ghost under the pointer, and one signal carrying the
tower and the release point. Wiring the signal to placement is T-0079 (the panel's
receiver) and T-0080 (the boot's connection), so the shipped app still uses click-then-tile
at the end of this task; the demo proves the bar's gesture in isolation, on the real boot
path.

## Contract (the next two tasks depend on this exact shape)

```gdscript
signal tower_drag_started(instance_id: int)
signal tower_dropped(instance_id: int, screen_point: Vector2)
```

`tower_drag_started` exists because **every bar selection opens the tower window** (the
boot wires `tower_selected` to `_on_tower_open_requested`). A press that becomes a drag
therefore pops that window over the board unless the boot is told a drag began. Emit it
once when a drag starts, never for a placed tower or a locked one. T-0078 only proves the
signal; T-0080 closes the window with it.

- **Start:** left press on a tower slot holding a tower that is **in hand**. The press
  keeps today's meaning — the slot is selected and the panel arms it — and additionally
  begins a drag. A **placed** tower does not begin a drag (its click opens the window).
- **Move:** mouse motion while the drag is live moves a ghost slot that follows the
  pointer and shows the tower's type and tier.
- **Release:** if the pointer has moved further than `drag_threshold_px` and the release
  point is **outside the bar's own rect**, emit `tower_dropped` once with the instance id
  and the release position in viewport coordinates (the coordinate space
  `MapInput.intent_for()` already reports). Then hide the ghost and end the drag.
- **Release inside the bar, or without passing the threshold:** no signal; the drag ends
  as a click. The selection stands.
- **Wave lock:** while `set_wave_locked(true)` is in force, no drag starts.
- The release is consumed by the bar while a drag is live (`set_input_as_handled`), so
  nothing else answers the same gesture.

The point is in viewport coordinates because the receiver resolves it with the same
`_pointer_world()` a click uses. Do not convert to world here: the bar does not own the
board's transform.

## Scope

1. The gesture above, in `src/ui/inventory_bar.gd`, with the ghost as one persistent
   child (not rebuilt with the slots) so `_rebuild()` cannot free it mid-drag. Store the
   drag as scalars (id, press point, current point), never as a node: `_select()` rebuilds
   the slot row on press.
2. Exported tuning: `drag_threshold_px` (range 2-24, default 6). Ghost size follows
   `_slot_side()`. No new colours unless needed; reuse the selection colours.
3. Read-back API for the demo, next to `slot_rect()` / `slot_state()`:
   `drag_active() -> bool`, `drag_instance() -> int`, `drag_point() -> Vector2`,
   `ghost_rect() -> Rect2`, `ghost_text() -> String`.
4. Pointer-only affordance: gamepad and keyboard keep the click-then-tile path. Say so
   in the header. Drag reads mouse button/motion directly (the router has no drag intent);
   the press still goes through `MapInput` for the selection, as today.
5. `src/ui/tests/inventory_migration_demo.gd` gains the cases below. Keep every existing
   case green. Put the new cases **after** the existing placement case and before the
   acceptance frame, so the frame is unchanged.

## Definition of done — one demonstration

1. `--check-only` pasted after every edit; final one pasted.
2. On the real boot path with **pushed mouse events** (the demo's existing
   `get_root().push_input()` helpers), prove:
   - press on an in-hand slot: `tower_drag_started` fires **once** with the dragged id,
     and no second time for a placed tower or while locked;
   - motion 200 px onto the board: `drag_active()` true, the ghost is visible, its rect
     centres within 2 px of the pointer, and `ghost_text()` names the tower and tier;
   - release there: `tower_dropped` fired **once**, with the exact id and the release
     point (within 1 px); `drag_active()` false; ghost hidden;
   - press and release inside the bar (no motion past the threshold): no signal;
   - a **placed** tower's slot starts no drag (use the tower the existing case placed);
   - `set_wave_locked(true)` suppresses a drag; unlock restores it.
3. **Planted failure:** make the release path return before emitting (or set
   `drag_threshold_px` beyond the test's travel), show the demo failing on the missing
   `tower_dropped`, then revert and show green. Paste the failing line.
4. No acceptance frame in this task: the visible end-to-end artifact (a tower placed by a
   drop) is T-0080's frame. The ghost is asserted as a resolved, visible node here, not as
   a flag (L-041).
5. `tests.ps1` 5/5. Smoke is not required: this file is a view with no gameplay path.
