# T-0039 — Waves that escalate across the run

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2B — core systems
Status: open

## Goal

A level's waves are defined data, not hardcoded spawning, and they get harder as the
**level index** grows — so a player whose inventory has grown meets a proportionate
challenge.

## Context

- `src/gameplay/arena.gd` already spawns on an interval and counts kills, leaks and stucks
- `docs/design/systems/waves.md` — being rewritten by T-0038 in parallel; use its shape if
  it lands, otherwise keep `PLACEHOLDER` values
- `docs/CHARTER.md` — difficulty scales on level index only; "broken builds" are the
  intended feature, so no anti-snowball mechanics
- `docs/LESSONS.md` — L-033 (`--check-only` per script), L-035 (assert on output)

## Scope

- A wave definition as data: list of (enemy type, count, spacing) plus a level multiplier
  derived from the **level index**.
- Level 1 wave 1 must stay gentle enough for one tier-1 tower (the existing suite case
  depends on a walker reaching the lane end quickly).
- An **elite** level's final wave carries **one sub-boss**, chosen at random from the two.
- Between waves, the phase returns to build; the wave ends when every spawned enemy is
  dead or leaked.

## Definition of done — with planted failures

1. `--check-only` output pasted for every script touched.
2. A headless demo printing, for level 1 and level 5, the wave count, total enemies and
   total enemy health — showing the escalation as **numbers**, not a claim.
3. `ARENA_SUMMARY` still carries the keys `smoke.ps1` reads (`stuck`, `spawned`,
   `despawned`, `live`), and `smoke.ps1` still passes at its short duration.
4. **Planted failure A:** a wave definition with zero enemies must fail loudly with a
   printed reason, not hang or silently skip.
5. **Planted failure B:** an elite level must spawn exactly one sub-boss on its final wave;
   break the selection so it spawns two, and show the assertion catching it.
6. `scripts/tests/run.ps1` still green.
