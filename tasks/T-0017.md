# T-0017 — Give scripts/ one owner and close the remaining unowned paths

Owner: human
Milestone: G2 — Vertical slice
Branch: `task/T-0017-ownership-fix`
Status: done

## Goal

Close the ownership gap that blocked T-0014, and remove the last unowned paths so
the next brief does not discover another one mid-dispatch.

## Context

`scripts/gate/perf.ps1` documents `scripts/perf/benchmark.tscn` as the place the
benchmark must live, and T-0014 followed that instruction. Neither `OWNERSHIP.md`
nor `eng/tools`' permission list had a row for `scripts/perf`, so the agent was
denied mid-task. It stopped correctly and proved the method on a throwaway probe:
1 000 entities → 703 fps, 20 000 → 49 fps with p99 31.9 ms.

Six near-identical `scripts/<dir>/**` rows had accumulated, and every new tooling
directory repeated the escalation. `docs/ASSETS.md` was also unowned.

## Change

- Collapse the six `scripts/<dir>/**` rows into `scripts/**` → `eng/tools`.
- `eng/tools` edit allow becomes `scripts/*`, which covers nested paths.
- Add `docs/ASSETS.md` → human.

`.opencode/**`, `opencode.jsonc` and `.github/workflows/**` were already assigned by
earlier work and are untouched here.

## Definition of done

- `eng/tools` can create `scripts/perf/benchmark.tscn` without a denial.
- No other agent gains access to `scripts/`.
- No path in `OWNERSHIP.md` remains unowned except deliberate exceptions.
- T-0014 re-dispatches and completes the harness.

## Do not

Do not widen any specialist's edit scope beyond `scripts/**` for `eng/tools`, and do
not change gate criteria.
