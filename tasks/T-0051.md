# T-0051 — Real gamepad bindings for the game's inputs

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2D — input
Status: open

## Why

The map screen routes input through Godot's built-in `ui_down` / `ui_up` / `ui_accept` /
`ui_cancel`, on the assumption that they already carry joypad events. A demo assertion
measured that assumption and it is **false in this project**: no joypad binding is present.

The charter states the game must be fully playable on a gamepad from the first prototype.
Right now that is a claim with nothing behind it.

## Work

1. Define four explicit actions in `project.godot`, each with **keyboard and joypad**
   events:
   - `game_focus_next` — Down arrow + D-pad down
   - `game_focus_prev` — Up arrow + D-pad up
   - `game_confirm` — Enter and Space + south face button (joypad button 0)
   - `game_dismiss` — Escape + east face button (joypad button 1)
   Use a reasonable deadzone for any axis bindings; prefer buttons to axes for focus.
2. Keep every existing built-in action untouched — other code may rely on them.
3. Print the resulting `InputMap` contents as evidence: for each new action, the event list
   with device and button/key indices.

## Constraints

- Write `project.godot` only.
- **40 steps, last 8 reserved** for verification and the envelope.

## Definition of done — with a planted failure

1. A headless script or scene that prints each new action and its events, showing at least
   one keyboard and one joypad event per action. Paste it.
2. **Planted failure:** remove the joypad event from one action in a **copy** (or via
   `scripts/gate/prove-failure.ps1`), show the check reporting that action as
   keyboard-only, and restore. Do not leave the project file mutated.
3. The project still imports cleanly and `scripts/gate/import.ps1` passes.
4. `scripts/tests/run.ps1` still 5/5.

## Return

The standard envelope with the InputMap dump, the planted failure, and `FILES TOUCHED`.
