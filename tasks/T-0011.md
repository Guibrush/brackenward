# T-0011 — G2 readiness fixes from external verification

Owner: `eng/tools`
Milestone: G1 repair, before G2 starts
Branch: `task/T-0011-g2-readiness`
Status: done

## Goal

Make the asset gate actually work, and remove the contradictions between the gate
result files and the signed gate definitions.

## Context

An external verification pass over the signed G1 found four defects:

1. `scripts/gate/assets.ps1` declared `param()` after executable statements.
   PowerShell requires it first, so it was parsed as a command: the switch never
   bound, `-PlaceholdersForbidden` was dead, and every run printed a red error
   block. This is the failure `L-019` warns about.
2. The manifest in use had evolved past `docs/ASSETS.md`: entries omit `type`, and
   `frames` is a count rather than a list of files. The gate failed on both.
3. The palette check flagged probe evidence (`status: raw-evidence`) intended to
   document the generator's raw output.
4. Two probe entries had no `licence`, contradicting the documented rule.

Separately: `G0-result.md` and `G1-result.md` still read "awaiting human
signature" while both definitions are signed, and `STATE.md` carried a stale date
and command count.

## Constraints

Only the gate script, the asset manifest, and documentation. No product code. No
gate criterion, threshold, or recorded signature changes.

## Definition of done

- `assets.ps1` exits 0 on the current manifest.
- `assets.ps1 -PlaceholdersForbidden` exits 1 and reports G4.8.
- `docs/ASSETS.md` describes the manifest as it is actually used.
- Result files point at the canonical signature; `docs/gates/README.md` states
  where the signature lives.
- Every manifest entry has a licence.
- The G0–G1 suite still passes 7/7.

## Do not

Do not weaken the palette check for shipping assets, and do not delete the probe
evidence — it is the record of the projection decision.

## Return

Standard envelope.
