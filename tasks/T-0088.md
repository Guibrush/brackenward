# T-0088 — Placement actions in the input map

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2I — controller placement
Status: open

## Goal

The controller placement mode needs horizontal movement, and the project input map has
only up/down (`game_focus_next` / `game_focus_prev`). Add **left** and **right** as data
in `project.godot`, with keyboard and joypad bindings, and a gate case that proves it.

## Actions to add

| Action | Keyboard | Joypad (device -1) |
| --- | --- | --- |
| `game_move_left` | Left arrow (physical 4194319) and A (65) | D-pad left, button 13 |
| `game_move_right` | Right arrow (physical 4194321) and D (68) | D-pad right, button 14 |

- `deadzone` 0.5, same shape as the existing four actions.
- Do **not** change `game_focus_next`/`prev`/`confirm`/`dismiss` or their bindings. Up and
  down stay on the existing two actions; this task adds the horizontal pair only.
- Keep the actions' names as written: `map_input.gd` and the tests will use them.

## Gate case

Add `scripts/tests/cases/input_bindings.gd` (extends the suite, overrides `_boot()` like
`systems_inventory.gd` so no scene boots) that asserts:

- all six placement/menu actions exist: the four existing plus `game_move_left` and
  `game_move_right`;
- each has at least one `InputEventKey` and one `InputEventJoypadButton` (the charter's
  "gamepad and keyboard are equal ports" is the point);
- `game_move_left` carries Left and A with pad button 13; `game_move_right` carries Right
  and D with pad button 14;
- the existing four actions still carry their current keyboard and pad events (no silent
  rebind).

## Constraints

- Write `project.godot` and `scripts/tests/cases/input_bindings.gd` only.
- **20 steps**, last 5 reserved for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/tools`, `Task: T-0088`.
- Zero generations.

## Definition of done

1. `tests.ps1` green with the new case: paste the case's `TEST_RESULT` line and the
   `G2 tests` summary (the count becomes 6 cases).
2. Paste the `git diff -- project.godot` and the case's output naming each action and its
   device kinds.
3. A headless `--path . --quit-after 1` (or whatever the gate uses) starts without an
   input-map error.
4. `git status --porcelain` and a clean-tree statement.

## Return

The standard envelope with the case evidence, the binding list, and `FILES TOUCHED`.
