# T-0002 — Write the CI workflow

Owner: `eng/tools`

## Goal

A GitHub Actions workflow exists that reproduces the local gate suite on a clean
Windows runner. This is what G1.4 measures and what G1.7 compares against — CI must
agree with local, on the same commit, or the gate is meaningless.

`.github/` does not exist yet. You are creating it.

## Context

Read first:

- `docs/gates/G1-bootstrap.md` — criteria G1.4 and G1.7
- `scripts/gate/all.ps1` — what a full gate run is, and its parameters including the `-Skip` switch used for `repo`
- `scripts/gate/gate.config.ps1`, `scripts/lib/common.ps1` — shared paths and helpers the gate depends on
- `docs/adr/0001-engine-version-policy.md` — the engine version is pinned and CI must use the same one
- `docs/LESSONS.md` — L-005 (`--import` alone is not a script check) and L-013 (run the gate while authoring)

Known environment facts, verified today:

- Godot **4.7.2** stable, Windows x64. Headless commands need `Godot_*_console.exe`.
- `gh` is authenticated as `Guibrush` with `repo` and `workflow` scopes.
- The repository does not exist yet; this workflow cannot run until T-0003 creates it.

## Constraints

- You may write: `.github/workflows/**` only.
- Do not modify any script under `scripts/`, any doc, or `project.godot`.
- No secrets, no API keys, no paid services in the workflow. It must run on a fresh
  public-repo runner with nothing configured.
- Pin the Godot version explicitly; do not install "latest" at run time, because
  ADR-0001 makes a version change a deliberate, signed event rather than a surprise.
- Budget: no paid generation.

## Definition of done

1. `.github/workflows/gates.yml` exists, triggered on push to `dev` and `main` and on
   pull requests targeting `dev`.
2. It checks out the repository, obtains Godot 4.7.2 into the expected
   `%LOCALAPPDATA%\Programs\Godot\` location so the gate scripts find it, and runs:
   `powershell -NoProfile -File scripts/gate/all.ps1 -Gate G1 -Skip repo`
3. `repo.ps1` is deliberately **not** run in CI (branch protection needs admin scope
   a workflow token lacks). State this in a comment in the file so nobody "fixes" it
   later.
4. The exact command in step 2 passes locally right now — paste its output. This is
   the only thing you can prove before the repository exists.
5. The YAML parses. Prove it with a real parser, not by eye; if no YAML parser is
   available on this machine, say so and name what would settle it.
6. The workflow is named so that the required status check is `gates` — protection
   will require that exact context, and a mismatch will make G1.2/G1.3 fail.

## Do not

- Do not run `init-repo.ps1` or `git init`; that is T-0003.
- Do not add a second workflow, a lint job, or a release job. One check, one context.
- Do not weaken `all.ps1`'s parameters to make CI easier; if a gate genuinely cannot
  run in CI, report it rather than exempting it quietly.

## Return

The standard envelope. In EVIDENCE include: the local `all.ps1 -Gate G1 -Skip repo`
output with its exit code, the YAML parser result, and the exact status-check name
the workflow will register.
