# T-0090 — The bar can be driven by a controller

## Goal

Give the inventory bar a controller face: left/right moves a **focus** across the tower
slots, confirm selects/arms the focused tower, dismiss clears it. The focus is visible
and is separate from the selection cue. This task builds the bar's API; the panel will
drive it in T-0091.

## Bar API

```gdscript
func focus_tower(delta: int) -> int      # moves focus by ±1, wraps; returns the id or -1
func focused_instance() -> int           # -1 when nothing is focused
func activate_focused() -> bool          # _select(focused, "pad") - the selection door
func clear_focus() -> void
func focus_rect() -> Rect2               # the drawn frame's rect, empty when hidden
```

- Focus lives on the **current page's tower slots** (no paging change).
- `focus_tower` starts at index 0 when nothing is focused, wraps with `posmod`, and
  clears when the group is empty. If an inventory rebuild removes the focused slot,
  clamp to the last slot or clear.
- `activate_focused()` uses the existing `_select()` path (so `tower_selected` is raised
  and the panel arms the tower); it does **not** raise `tower_clicked`, so no window
  opens on a controller selection.
- `clear_focus()` hides the frame; `unbind()` clears it too.

## Visual

- A `ReferenceRect` named `FocusFrame` added as the bar's last child: `mouse_filter =
  IGNORE`, `visible = false`, `border_width` from a new export (default 2), colour from a
  new export (default near-white, distinct from the selection tint and the three state
  borders).
- It frames the focused slot (slot rect expanded by 1 px), repositioned after any rebuild
  or page change. State remains the slot's border; focus is the frame, so neither cue
  hides the other.
- `focus_rect()` reads the frame's rect (empty when hidden), the same convention as
  `ghost_rect()`.
