# T-0014 — Performance harness that can fail

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 1 — blocks every later performance claim
Branch: `task/T-0014-perf`
Status: open

## Goal

`scripts/gate/perf.ps1` measures real frame times against the G2 budget instead of
blocking. Today it documents the method and implements nothing, so G2.3 cannot pass
and no performance claim in the slice is checkable.

## Context

Read first:

- `scripts/gate/perf.ps1` — the intended method, already written as comments
- `docs/gates/G2-vertical-slice.md` — G2.3 and the signature block's perf fields
- `scripts/gate/gate.config.ps1`, `scripts/lib/common.ps1` — shared helpers
- `art/STYLE.md` — the declared resolution is 1920×1080 at 2× scale
- `docs/LESSONS.md` — **L-021** (a check never observed failing is not evidence) and L-016 (leaf scripts propagate failure)

## Budget under test

- `fps_avg >= 60`
- `frame_ms_p99 <= 20` (equivalently 1 % low >= 45 fps)
- Resolution: 1920×1080, declared in the gate output so the number is not anonymous

## Constraints

- You may write: `scripts/gate/perf.ps1`, `scripts/perf/**`, and a benchmark scene
  under `scenes/` **only if** `scripts/perf/benchmark.tscn` cannot live there. Prefer
  `scripts/perf/benchmark.tscn` as the gate expects that exact path.
- Do not change the budget. It lives in the gate document; `perf.ps1` reads it.
- Do not measure headless: a headless frame time is not a rendered frame, which is
  why this was blocked in the first place.
- You may add a minimal benchmark scene with N entities; it does not need the game.
- Budget: no paid generation. This task costs nothing.

## Definition of done

1. `scripts/perf/benchmark.tscn` exists, runs a fixed scripted sequence with a known
   entity count, and emits one JSON line per 60 frames with `frame_ms_p50`,
   `frame_ms_p99`, `fps_avg`.
2. `perf.ps1` runs it **windowed**, parses those lines, reports the resolution, and
   compares against the budget.
3. **Exit 0 on a passing run — observed.** Paste the output.
4. **Exit 1 on an over-budget run — observed.** Produce the over-budget condition by
   adding load (more entities or an explicit stress flag), not by lowering the budget
   or faking a number. Paste the output. This is the whole point: L-021 says a check
   that has never failed is not evidence.
5. Both runs are deterministic enough to be re-run: state how many entities each run
   used and what the measured numbers were.
6. `all.ps1 -Gate G2` no longer reports `blocked` for G2.3 (it may pass or fail on
   performance, but it must produce a measurement).
7. **Do not run any git command.** `studio-lead` is the only committer
   (`docs/GIT.md`); return `FILES TOUCHED` with exact paths and the numbers, and the
   commits will carry `Agent: eng/tools` and `Task: T-0014` trailers.

## Do not

- Do not make the benchmark scene depend on gameplay code that does not exist yet.
- Do not tune the entity count until the numbers pass; report what the machine does.
- Do not add a `--force` bypass of any kind.
- Do not run `git add`, `git commit`, `git switch`, `git checkout`, or `git stash`.

## Return

The standard envelope with both runs' output, the entity counts, the measured numbers,
and `FILES TOUCHED` as exact paths.
