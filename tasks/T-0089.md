# T-0089 — MapInput knows the horizontal placement intents

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2I — controller placement
Status: open

## Goal

`game_move_left` / `game_move_right` exist in the input map (T-0088); `MapInput` must
translate them like the other four actions, so a screen never reads an action name.

## Change

1. `src/ui/map_input.gd`:
   - extend `Intent` with `MOVE_LEFT` and `MOVE_RIGHT`, and `INTENT_NAMES` with
     `"move_left"` / `"move_right"`;
   - add `ACTION_MOVE_LEFT = &"game_move_left"` and `ACTION_MOVE_RIGHT =
     &"game_move_right"`;
   - in `intent_for()`, check them after the existing four (order matters only in that
     nothing else consumes the same event);
   - include them in `action_names()`;
   - update the header's contract: up/down stay on `game_focus_*`; left/right are the
     placement pair, and the four existing intents are unchanged.
2. `src/ui/tests/input_route_demo.gd`: one new case near the top, before the walk:
   - build a `MapInput` and feed it real `InputEventKey` presses for `KEY_LEFT` and
     `KEY_RIGHT`;
   - assert `intent_for()` returns `MOVE_LEFT` / `MOVE_RIGHT` with the keyboard device,
     and that a `KEY_UP` still returns `FOCUS_PREV` (the existing mapping is untouched);
   - print one `INPUT_ROUTE_INTENT` line per event with the name and device.
   Keep every existing case green.

## Constraints

- Write `src/ui/map_input.gd` and `src/ui/tests/input_route_demo.gd` only.
- **25 steps**, last 6 reserved for verification and the envelope.
