# T-0019 — Implement ADR-0004: peak-normalised one-shots

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 1b — unblocks all batch audio
Status: open

## Goal

The audio gate and post step measure short one-shots the way the mix treats them:
true peak for assets under 1 s, integrated LUFS for everything at or above 1 s.
Read `docs/adr/0004-short-sfx-peak-normalisation.md` first — it is the authority,
and its rationale matters more than its table.

## `scripts/gate/audio.ps1`

- Assets **≥ 1 s**: gate on integrated LUFS exactly as now (music −18, ambience −20,
  tolerance ±2 LU).
- Assets **< 1 s**: gate on **true peak ≤ −1 dBTP**. Integrated LUFS is still
  measured and printed, labelled **advisory**; it must not gate and must not vanish.
- Both numbers are reported for every asset.
- Duration is read from the file, not from the manifest, so a mis-declared duration
  cannot dodge the loudness check.
- **No placeholder exemption.** That is the trap L-031 describes.

## `scripts/audio/post.ps1`

- **Peak-normalise short clips** instead of computing an EBU R128 gain. Sub-400 ms
  input currently reads the −70 LUFS floor and applies an enormous meaningless gain;
  that is a bug, not a tolerance question.
- **Trim trailing silence for `kind: sfx`.** An untrimmed tail is what put a 20 ms
  click inside a half-second file.
- Keep the existing −1.5 dBTP limiter behaviour for everything else.

## The committed probe

`assets/audio/sfx/sfx_ui_click_01.wav` measured −29.1 LUFS with peak −2.0 dBTP. Under
the new rule the peak passes. Handle it deliberately and say which you did:

- verify it against the new gate as it stands, **or**
- if it must be re-processed, note that `gen-sfx.ps1` deletes the raw MP3, so
  re-processing is impossible without another paid call — do **not** spend one
  without approval; leave the file and report.

Do not leave a failing asset with a manifest entry in `assets/`.

## Definition of done — all three observed, with numbers

1. **The existing sfx probe passes the new peak rule** (or a replacement that you
   generate locally, free, does). Paste the gate output with the measured dBTP and
   the advisory LUFS.
2. **A deliberately hot file fails.** Create a locally generated clip whose true peak
   exceeds −1 dBTP and show the gate exiting 1 with the number. Then show the
   corrected version passing.
3. **A ≥ 1 s loop still gates on integrated LUFS.** Generate a synthetic ≥ 1 s file
   locally with ffmpeg, register it temporarily if the gate needs a manifest entry,
   show the LUFS check gating (including one failing case), then remove it. Paste
   both.
4. Address the `G2.7.s` "no looping entries declared" state: as written it blocks the
   whole gate when no loop exists, which would keep G2.7 at exit 3 forever. Resolve
   it explicitly and state the reasoning — a check with nothing to check is
   *not applicable*, not silently passed, and not a permanent block. Do not let a
   vacuous pass hide future loops.
5. Report the numbers for every run, not verdicts.
