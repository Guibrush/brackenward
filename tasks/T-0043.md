# T-0043 — RunState follows ADR-0006

Owner: `eng/systems`
Milestone: G2 — Vertical slice
Wave: 2B — reconciliation
Status: open

## Goal

`RunState` stops pretending a run has a fixed level count. `docs/adr/0006-run-level-count.md`
is the authority; implement it.

## What ADR-0006 decides

1. `start()` takes **no level count** — only `hq_max` and `starting_gold`.
2. `RunState` **counts levels completed**, never a total. `level_index()` advances only
   when a **level-type** node is completed.
3. Non-level nodes (`store`, `rest`, `treasure`, `event`, `boss_preview`) **do not** advance
   the level index.
4. **Victory is completing the boss node** — `complete_level()` plus an explicit
   `win_run()`, called by whoever owns the map.
5. `run_map.max_levels()` is a **ceiling**, never a loop bound.
6. Tests asserting a fixed count are rewritten to assert on the **sequence of completions**.

## Definition of done — with planted failures

1. `--check-only` pasted for both files.
2. Selftest passing, one summary line, with the existing cases rewritten: a three-level
   sequence driven by completions, gold in and out, HQ carried.
3. **Planted failure A:** completing a level after `win_run()` is refused with a printed
   reason, and the level index does not move.
4. **Planted failure B:** a store-type stop between two level completions leaves the level
   index unchanged — print the index before and after, so "non-level nodes are not levels"
   is evidence rather than prose.
5. **No fixed count survives:** grep `run_state.gd` for `level_count` and show it absent
   (or, if something must remain, print it and justify it).
6. The no-save assertion still holds.
