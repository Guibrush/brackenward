# T-0077 — Corner block refreshes what it draws

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2H — inventory interaction
Status: open

## Goal

The corner block's labels show the live HQ and wave values. Today the block renders the
scene's static text (`HQ 0/0`, `Wave 0/0`) and never updates, because the panel's exported
node paths still name the pre-T-0076 tree. Fix the binding, and make a demo assert the
**text on the label**, not the dictionary the panel reports.

## Diagnosis (verified, not assumed)

- `scenes/build_panel.tscn:44-76` puts the column at `Block/Margin/Column/*`.
- `src/ui/build_panel.gd:225-237` still exports `Margin/Column/*` for Title, State, Wave,
  Actions, Status, Reason and Hint. `_node()` therefore returns `null`, and every `_sync_*`
  writes nothing. `margin_path` was updated in T-0076; the copy paths were not.
- The shipped demos missed it because `BUILD_PANEL_SHOWN` prints `state()`/`wave()` (live
  reads), and `src/ui/tests/inventory_migration_demo.gd` reads the label through the same
  broken path and reports `<missing>`.
- Evidence from today: `inventory_migration_demo` fails with
  `the panel's state line still carries HP: '<missing>'`.

## Scope

1. Point all seven exported copy paths at the real tree (`Block/Margin/Column/...`). Change
   defaults in the script; do not hardcode `$` lookups and do not move the scene back.
2. Keep the state line's wording as T-0076 left it (`HQ %d/%d`). The old `HP` assertion in
   `inventory_migration_demo` is stale and must be corrected to match what ships.
3. Strengthen `inventory_migration_demo` so it proves **visible text equals live value**:
   - the state label's `text` equals `panel.state()["label"]`;
   - the wave label's `text` equals `panel.wave()["label"]`;
   - the status label's node exists;
   - change a live number (damage the HQ through the run, as the demo already can) and the
     label follows without a manual refresh call.
4. Do not change gameplay, signals or the scene layout.
