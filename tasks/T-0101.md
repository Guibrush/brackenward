# T-0101 — Wire the tower sprites into the tower scene

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2J — art integration
Status: open

## Goal

`scenes/tower.tscn` still draws polygons. Every tower type now has a shipped 64×64 idle
sprite at `assets/art/towers/<type>/idle/south.png` (arrow, ballista, mortar, rime,
beacon, bramble). Show the sprite for a known type and keep the polygons only as a
fallback.

## Scene

`scenes/tower.tscn`: add a `Sprite2D` named `Sprite` between `Body` and `TierMark`:
`visible = false`, `centered = false`, `position = Vector2(-32, -63)`,
`texture_filter = 1` (nearest). Keep `Base`, `Body` and `TierMark` as they are for the
fallback and the tier cue.

## Script

`src/gameplay/tower.gd`:

- `@export var sprite_path: NodePath = ^"Sprite"` and
  `@export var sprite_format: String = "res://assets/art/towers/%s/idle/south.png"`.
- Resolve the sprite in `_ready`; a `_apply_art()` called from `sync_from_instance()`
  sets the texture when `ResourceLoader.exists(sprite_format % type_id)`; otherwise it
  clears it.
- When a texture is shown: `Sprite.visible = true`, `Base` and `Body` hidden. When not:
  the polygons are shown exactly as today.
- `_update_visual()` keeps the tier logic for the polygon fallback, but a sprite tower is
  not scaled by tier: the tier stays visible through `TierMark` (the amber square, a
  placeholder until the pip glyph exists). Keep `TierMark` above the sprite.
- No change to targeting, firing, tier adoption, `invested()`, or the instance sync.

  flake (L-043/L-044).
- `git status --porcelain` and a clean-tree statement.
