# T-0080 — Wire the drop, close the window, prove it end to end

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2H — inventory interaction
Status: open

## Goal

The boot connects the bar's drag to the panel: releasing a dragged tower over a build
tile places it with no demo calling the receiver, and starting to drag closes the tower
window that the press opened. This is the task that makes drag-and-drop real.

## What to change

1. `src/ui/boot.gd`, `_wire_level_panel()`:
   - connect `bar.tower_dropped` to `panel.drop_tower`, guarded on both the signal and
     `panel.has_method("drop_tower")`;
   - connect `bar.tower_drag_started` to a small boot handler that closes the tower
     window if it is open, and prints one line naming the instance and whether it closed;
   - report both in the existing `BOOT_WIRED` line (e.g. `"drop": true`,
     `"drag_closes_window": true`) so a wiring that silently did not happen is visible.
2. `src/ui/tests/inventory_migration_demo.gd`:
   - **Remove the manual `_panel.drop_tower(...)` call** in case 4c. The release now
     places through the boot; derive the result from the board (`_arena_has_tower`,
     the arena's slot list), not from a return value.
   - During the 4c drag, after the motion past the threshold, assert the tower window is
     **closed**: the press opened it, `tower_drag_started` closed it. This is the visible
     half of the wiring.
   - The T-0078 release at `(44, 387.5)` is over bare ground (335.9 px from the nearest
     tile). With the wiring it now reaches the arena, which refuses it: assert the tower
     stays in hand, nothing is placed, and the panel shows the arena's refusal sentence.
     Do not change the T-0078 point.
   - Keep the direct `drop_tower` calls only for the second-drop and in-bar refusals, which
     cannot be produced by the bar (a placed slot cannot drag; an in-bar release never
     emits).
3. Keep every other case and the final frame's composition unchanged.
