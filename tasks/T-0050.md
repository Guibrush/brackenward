# T-0050 — The map screen: choose the next node

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2D — UI
Status: open

## Goal

The player can see the run map and choose where to go next. Without this, a run cannot be
started by a human at all — every other piece works headlessly.

## Context

- `src/gameplay/run_flow.gd` — `start_run(seed)`, `visible_nodes()`, `enter_node(id)`,
  `snapshot()`; the map exposes `is_visible`, `is_selectable`, `knowledge()` (type,
  dominant enemy types, active tile count)
- `docs/design/systems/nodes.md` — what each node type shows when revealed
- `docs/CHARTER.md` — gamepad-first is a stated constraint; mouse is the port, so keep input
  in one place that a controller can drive later
- `docs/gates/G2-vertical-slice.md` — G2.2 is a human playing a complete run

## Scope

A minimal screen, not a designed menu:

1. Show the run's current position and the **revealed** nodes — type, dominant enemy types
   and active tile count — as something selectable.
2. Only **selectable** nodes can be chosen; a visible-but-not-selectable node is shown, not
   clickable, and says why when asked.
3. Show the run's state: HQ current/max, gold, towers owned.
4. Choosing a node calls `enter_node()`; the screen disappears when a level opens and
   returns when the level completes.
5. Node types already implemented render distinctly by type name; no icons required at G2.

## Constraints

- Write `src/ui/**` and `scenes/**` only, plus the minimum `run_flow.gd` hook to emit
  "map is ready" and "level opened". Do **not** edit `src/systems/**`, `scripts/**`,
  `docs/**`, `project.godot`.
- **Gamepad-ready input:** every action reachable through a single input abstraction, even
  if only mouse is bound today. Say in the envelope what a controller would need.
- **40 steps, last 8 reserved** for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/gameplay`, `Task: T-0050`.
- Zero generations.

## Definition of done — with planted failures

1. `--check-only` per script, pasted.
2. A headless demo asserting: the screen lists exactly the visible nodes; a not-selectable
   node reports a reason; selecting a selectable node calls `enter_node` and the route
   advances; HQ and gold shown match `RunSnapshot`.
3. **Planted failure A:** force a node to be visible but not selectable and show the screen
   refusing to enter it while still listing it.
4. **Planted failure B:** break the snapshot binding (point it at a stale state) and show the
   demo catching the mismatch rather than displaying wrong numbers.
5. `tests.ps1` 5/5 and short `smoke.ps1` with `stuck 0`, no error lines.

The standard envelope with the demo output, both planted failures, the input abstraction's
shape, and `FILES TOUCHED`.
