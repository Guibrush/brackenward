# T-0064 — Make "armed" impossible to miss, and repair the stale demo

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2F — playability
Status: open

## Context

T-0063 established, with real pushed input events on the real boot path, that clicks and keys
**do** reach the panel and a click on the arrow row **does** arm it. The human still reported
"clicking on it didn't do anything", and the code's only feedback is a text suffix
(`armed_marker = "armed"`).

That is a discoverability failure, not a delivery failure. Fix the feedback, not the plumbing.

## Work

1. **Unmistakable armed state.** The armed row must be visibly different — background colour,
   border, or a leading marker *and* the row text — and a status line must say what to do next:
   *"arrow armed — click a build tile to place it"*. One glance must answer "did my click
   register?".
2. **Same for selection.** Clicking a placed tower must show whose actions are on screen.
3. **Repair `src/ui/tests/build_panel_demo.gd`** — its check `"the panel ships inside the level
   scene"` looks the panel up by its old path and now fails. Find it the way
   `build_panel_boot_demo.gd` does (search the level subtree for a Control with `bind_arena`).
4. `--headless --import` so `input_route_demo.gd.uid` exists, then `tests.ps1` 5/5 and a short
   `smoke.ps1`.

## Constraints

- Write `src/ui/**` and `scenes/**` only; no `src/systems/**`, `scripts/**`, `docs/**`,
  `project.godot`.
- **40 steps, last 8 reserved** for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/gameplay`, `Task: T-0064`.
- Zero generations.

## Definition of done — with a rendered frame

1. `--check-only`, pasted.
2. A demo pushing **real events** (as in `input_route_demo.gd`) asserting the armed row is
   visually distinguishable — its colour or marker differs from every other row — and that the
   status line names the next action.
3. **A rendered frame** from `--write-movie` on the boot path with a tower armed, saved outside
   the repo, path reported. This is the acceptance evidence: the human looks at it.
4. `build_panel_demo.gd` passes again; `tests.ps1` 5/5; short `smoke.ps1` unchanged.
5. **Planted failure:** in a copy, remove the visual cue and show the demo failing on "the armed
   row is visually distinguishable"; restore, hash unchanged.
