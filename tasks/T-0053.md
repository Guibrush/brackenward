## Two jobs

### 1. `--autostart` must survive a 300 s gate run

`smoke.ps1` runs the main scene headless for 300 s and asserts a scene-reported duration of at
least 298 s. Once `main_scene` is the boot scene, an autostart run can be won or lost in two
minutes, after which the boot sits on a menu with no `ARENA_SUMMARY` — and G2.1.4 goes red for
a reason that has nothing to do with stability.

Make `--autostart` **keep playing until the session time expires**: when a run ends, start
another immediately, for as long as `--seconds` allows. The arena must stay alive long enough
to report; the last summary still prints. This is what a stability criterion should exercise —
a game that runs, not a menu that idles.

### 2. Run the two planted failures as real copy mutations

The previous pass asserted them in-demo but never demonstrated them on a mutated copy. Do it
properly:

- **Failure A:** remove `start` from the menu's default entries in a **copy**, run the boot
  headless, show the menu rendering one row with no error.
- **Failure B:** make `_request_quit` a no-op in a **copy**, run the demo, show it returning
  `status: fail` and naming the exit path.

Mutate the copy only, delete it in `finally`, and print the real tree's hashes to show it was
untouched. `scripts/gate/prove-failure.ps1` has a closed registry and `scripts/**` is not your
path, so do the copy by hand — or report that you did.
