# T-0046 — Perf gate records the machine, not just the number

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2C — diagnosis
Status: open

## Why

`G2.3` passed for weeks at 651 fps, then went red at ~60 fps with no code change: the
machine's display dropped to 59 Hz with a Parsec virtual adapter in the path. The gate
named the renderer and resolution but not the refresh rate, so a capped machine looked
exactly like a regression (L-040).

## Work

1. Record and print, alongside the numbers: **screen refresh rate**
   (`DisplayServer.screen_get_refresh_rate()`), vsync mode, max fps, renderer, resolution
   and content scale — all already partly present — in both `PERF_INFO` and the gate's
   result block.
2. **Capped-display diagnostic:** if the measured `p50` is within 10% of the refresh
   period (`1000 / refresh_hz` ms) and the refresh rate is below 120 Hz, print one line
   naming it, e.g. *"p50 17.06 ms is one 59 Hz refresh period — the display is pacing
   frame delivery; this is not a code regression"*. It is **advice**, not a verdict: the
   pass/fail rule does not change.
3. **Do not weaken the budget.** 60 fps average and p99 ≤ 20 ms stay exactly as they are.

## Constraints

- Write `scripts/perf/benchmark.gd` and `scripts/gate/perf.ps1` only.
- **40 steps, last 8 reserved** for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/tools`, `Task: T-0046`.
- Zero generations.

## Definition of done — with a planted failure

1. A run on this machine prints the refresh rate and the capped-display diagnostic, with
   the measured `p50` shown against the refresh period. Paste it.
2. **Planted failure:** force the diagnostic's threshold to a value the current run cannot
   meet (or feed it a synthetic `p50`), show the diagnostic *not* firing when the numbers
   do not match, and restore. The check must be seen both firing and silent.
3. The pass/fail outcome is unchanged by the diagnostic: demonstrate one run where the
   diagnostic fires and the verdict stays whatever the budget says.
4. `perf.ps1` still exits 0 on a passing build and 1 on a failing one.

## Return

The standard envelope with both runs, the diagnostic text, and `FILES TOUCHED`.
