# T-0044 — Put the system selftests under the gate

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2C — protection
Status: open

## Goal

Four selftests currently prove a lot and guard nothing: `tests.ps1` only runs
`scripts/tests/cases/`, so 310 checks never execute in CI.

- `src/systems/tests/run_state_selftest.gd` — 116 checks, ADR-0006 behaviour
- `src/systems/tests/run_map_selftest.gd` — 5346 checks, map invariants
- `src/systems/tests/inventory_selftest.gd` — 100 checks, inventory rules
- `src/systems/tests/offers_selftest.gd` — 94 checks, store and offers

## Work

1. **Move** each into `scripts/tests/cases/` as a suite case, adapting it to the runner's
   contract (`scripts/tests/lib/suite.gd`): extend the suite base, emit the single
   `TEST_RESULT` line the runner requires, and let failures drive the exit code. Keep the
   assertions; do not weaken a check to make the move easier.
2. **Delete the originals** in `src/systems/tests/` so there is exactly one copy. This
   deletes files under a path owned by `eng/systems`; that exception is recorded in
   `docs/OWNERSHIP.md` for this task, and it exists so the suite cannot drift from a stale
   duplicate.
3. **Add one `prove-failure.ps1` case** named for these suites — a mutation that breaks a
   rule the suite asserts (for example the inventory cap check, or `RunState`'s refusal
   after victory). It must make the suite exit 1, and it must run the gate **inside a
   copy**, per the standing rule.
4. `tests.ps1` must report **five** cases (the existing leak case plus four) and name any
   failure.

## Constraints

- Write `scripts/tests/cases/**` and `scripts/gate/prove-failure.ps1` only.
- Do not change any assertion's meaning, any threshold, or `tests.ps1`'s pass criterion.
- **40 steps, last 8 reserved** for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/tools`, `Task: T-0044`.
- Zero generations.

## Definition of done — with a planted failure

1. `powershell -NoProfile -File scripts/gate/tests.ps1` runs **five** cases, all green;
   paste the output with each case named.
2. The four moved suites still report their original check counts (or the count that
   results from the format change, stated as a difference).
3. `src/systems/tests/` is empty of the four files, and `git status` shows the deletions.
4. **Planted failure:** run `prove-failure.ps1` with the new case; it reports the gate
   exiting 1 inside the copy with the failing assertion named, and the real tree is
   unchanged (`git status` identical before and after).
5. A suite that fails to parse is still reported as a failure, not skipped.
