# T-0038 — Revise the tables for inventory and the run map

Owner: `design/systems`
Milestone: G2 — Vertical slice
Wave: 2B — design revision
Status: open

## Why

The G0/G2 assumptions changed after the first tables were written. Towers now live in an
**inventory** and are placed for free; gold buys acquisition and tiers; runs are 5–10
levels on a **procedural map** with eight node types. `towers.md`, `economy.md` and
`waves.md` describe the old world and must be corrected before code follows them.

## What changed, from the human, verbatim in substance

- **Inventory.** Acquiring a tower or upgrade puts it in the inventory. Placement is
  **free**. Reconfiguration — picking towers back, placing others, equipping — is free and
  allowed between waves and between levels. Inventory is **uncapped for now** but must be
  built with a cap setting.
- **Duplicates allowed**, for towers and upgrades alike. Two copies of the same upgrade on
  one tower is allowed, behind a toggle.
- **Two upgrade slots per tower** (data-driven), and **two separate tier axes**: towers
  have 3 tiers, upgrades have 3 tiers, both paid separately in gold, both purchasable only
  in-level between waves on the build screen. Equipped upgrades can be tiered up.
- **Upgrades are permanent for the run** once applied — the replaced one is destroyed —
  with the implementation prepared to make them removable later.
- **Gold** buys: store items, rerolls, tower tiers and upgrade tiers. Never placement,
  never equipping.
- **Difficulty scales on level index only.** The intent is to let players build "broken"
  combinations: do not add anti-snowball mechanics.
- **Run map:** 9 layers between start and boss, 2–3 nodes per layer, at least one map node
  per layer, so a maximal run reaches 10 levels. Boss level is unique and final.
- **Node types:** map, store, elite, boss preview, treasure (gold), rest (HQ heal), event
  (choose among X towers/upgrades), high-stakes event (blind roll on arrival: HQ damage or
  a tower tier upgrade). Elite = a standard map whose final wave carries one of the two
  sub-bosses, chosen at random.
- **Store:** sells towers and upgrades, stock randomised per visit, max 5 items (data),
  tier-weighted with higher tiers rarer. Hidden rule: a store visited in the second half
  of the run guarantees at least one tier-2-or-better item.
- **Reroll** applies to the between-level offer and the store's stock, competing with
  purchases for gold, **toggleable per site**.
- **Starting loadout:** a choice between two tier-1 towers and two tier-1 upgrades.
- **Adopted hidden rules:** *familiar ground* — revisiting a map in the same run activates
  one extra build tile; *empty-handed bonus* — after 3 layers without a store, the next
  map node grants bonus gold (threshold data-driven).

## Work

1. **Rewrite `towers.md`** for the inventory model: acquisition vs placement, the two tier
   axes, 2 upgrade slots, duplicates, permanence. Remove the old per-placement cost model.
2. **Rewrite `economy.md`**: gold sources (kills, level completion, treasure, hidden
   bonus) and sinks (store items, rerolls, tower tiers, upgrade tiers). Redo the worked
   example around acquisition rather than placement, and re-derive the two sanity
   thresholds for the new model.
3. **Rewrite `waves.md`**: waves scale on level index; state the curve for a 5-level and a
   10-level run, and how the elite finale differs.
4. **Add `nodes.md`**: every node type, what it offers, weights, and the reveal rule
   (active tiles and dominant enemy types shown when the node is revealed on the map;
   wave composition hidden).
5. **Add `store.md`**: stock size, tier weighting table, the second-half guarantee, reroll
   toggle and cost.
6. **Add `hidden-rules.md`**: the two adopted rules with their parameters, plus the three
   rejected ones with the reason, so they are not rediscovered as new ideas.
7. **Add `run-map.md`**: 9 layers, 2–3 nodes, ≥1 map node per layer, the "previous map has
   the lowest but non-zero weight" rule, boss-final rule, and how the 5-vs-10 spread is
   reached.
