# T-0061 — The build panel never binds in the real game

Owner: `eng/gameplay`
Milestone: G2 — Vertical slice
Wave: 2E — playability
Status: open

## The bug, observed

Rendering the real boot path to a video and extracting a frame
(`--write-movie ... -- --autostart --seconds=3`, frame at 2 s) shows the level's lane, HQ and
walkers, plus the panel's **hint text only**. Missing:

- the Title, State (HP/Gold) and Wave labels — blank
- every row in the list — no tower rows, no Start Wave row

So the panel renders `Hint` and nothing else. The panel demos pass because they call
`bind_arena()` explicitly; the boot path never reaches a bound state.

The extracted frame is at `%TEMP%\opencode\diag_frame.png` for reference.

## Likely cause, to confirm not assume

`BuildPanel` is a child of `Arena` in `scenes/main.tscn`, and its `_ready()` runs **before**
the arena's. T-0057 added a check that waits for `arena.is_node_ready()`, but if that wait is
a single deferred call rather than a signal or a retry, the panel binds to a half-ready arena
or never binds at all — and then `_apply_copy()` has no arena to read, so the labels stay
blank and `_rebuild_rows()` produces nothing.

Confirm the actual path before changing it: log when `bind_arena()` is called, whether it
returned false, and whether `_rebuild_rows()` ran.

## Scope

1. The panel binds correctly when the arena is instantiated by the boot, not only when a demo
   binds it by hand.
2. Title, State, Wave, the tower rows and Start Wave all render in the real game.
3. No regression in the explicit-bind demos.
