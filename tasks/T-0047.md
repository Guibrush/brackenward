# T-0047 — Pin the benchmark to the NVIDIA GPU and a physical display

Owner: `eng/tools`
Milestone: G2 — Vertical slice
Wave: 2C — measurement rigour
Status: open

## Why

The perf gate now reports refresh rate, but three things remain uncontrolled:

- **GPU selection is implicit.** Godot accepts `--gpu-index <n>`; the harness does not pass
  it. If the machine ever has more than one render device, the benchmark measures whichever
  the driver picked.
- **Screen selection is implicit.** `--screen <n>` exists and the window lands wherever
  Windows chooses. A virtual display adapter (Parsec) is present on this machine, and a
  benchmark rendered onto a virtual or streaming display measures the wrong thing.
- **The harness cannot say which screen it used.** Refresh is recorded; screen identity is
  not.

## Work

1. **Enumerate the screens from inside the engine.** A small probe (or a flag on the
   benchmark scene) prints, per screen: index, size, refresh rate, and whether the refresh
   is reported at all. Write it into `PERF_INFO` as a list.
2. **Choose the benchmark screen deliberately:** the screen with the largest reported
   refresh rate; ties broken by area; a screen reporting 0 Hz (typical for a virtual
   adapter) is never chosen while a real one exists. If only virtual screens exist, say so
   loudly rather than measuring silently.
3. **Pass `--gpu-index 0` explicitly** and record the device name the engine reports, so a
   second render device cannot change the measurement quietly. If `--gpu-index` is
   rejected on this engine build, report that rather than dropping the flag silently.
4. **Print the chosen screen and GPU in the gate's result block**, alongside the existing
   renderer, resolution, refresh, vsync and max-fps lines.

## Constraints

- Write `scripts/perf/benchmark.gd` and `scripts/gate/perf.ps1` only.
- **Do not change the budget** or the pass/fail rule. 60 fps average and p99 ≤ 20 ms stay.
- **40 steps, last 8 reserved** for verification and the envelope.
- No git commands; `studio-lead` commits with `Agent: eng/tools`, `Task: T-0047`.
- Zero generations.

## Definition of done — with a planted failure

1. A run printing all detected screens with size and refresh, the chosen screen, and the
   GPU device name. Paste it.
2. **Planted failure:** force the chooser to pick a screen reporting 0 Hz (or the lowest
   refresh) and show the harness refusing or warning, rather than measuring on it silently;
   restore and show the normal choice.
3. The result block names screen and GPU, so a reader can tell which display produced the
   number without leaving the log.
4. Exit codes unchanged: 0 on a pass, 1 on a budget miss, 3 when blocked.

## Return

The standard envelope with the screen table, the chosen screen, the GPU name, the planted
failure, and `FILES TOUCHED`.
